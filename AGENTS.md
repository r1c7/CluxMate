# Project memory

## What CluxMate is

- CluxMate = one Python agent core (`cluxmate/`) driving three front-ends: headless CLI (`cluxmate -p "..."`), Textual TUI (`cluxmate`), and an Electron desktop (`desktop/`) over JSON-RPC stdio (`cluxmate agent stdio`). Providers are OpenAI-compatible only (`core/providers/` = base + openai + factory; no Anthropic provider).
- Four risk modes (`plan` / `default` / `acceptEdits` / `yolo`), per-session only, never persisted: `plan` registers ONLY read tools (no bash/write/delete/task/update_memory/MCP — hard isolation, nothing to approve); `default` auto-approves `safe` and asks for `write`/`dangerous`; `acceptEdits` auto-approves `write`; `yolo` disarms the sandbox boundaries entirely (the one explicit opt-out).
- Risk levels `safe` < `write` < `dangerous` < `critical`. `critical` (bash `format`/`mkfs`/`dd`/`> /dev/`/`chmod 777`) never auto-approves and is never always-allowable, like escalation. Running code (interpreters/build tools/scripts — `python`, `node`, `npm run`, `./x.sh`, …) is `dangerous`, never `safe`; classified by runner name with a `run` fallback for unlisted executables.
- Always-allow lives in `permissions.json` in two tiers: `always_allow_tools` (write risk) and `always_allow_dangerous_tools` (dangerous risk — `delete_file` whole-tool, and bash PER category `"bash:rm"` / `"bash:git-reset-hard"` / `"bash:python"` / `"bash:run"` / …, NEVER a bare `"bash"`). Escalation (`danger-full-access`), `critical` bash and MCP dangerous tools are never always-allowable.
- The repo root IS the git repo (branch `master`, remote `git@github.com:r1c7/CluxMate.git`). `.gitignore` excludes `docs/`, `scripts/`, `.cluxmate/`; `snapshots/*.png` (UI screenshots) ARE tracked. Undo checkpoints are a SEPARATE shadow repo at `~/.cluxmate/checkpoints/<sha1(cwd)>.git` (env GIT_DIR/GIT_WORK_TREE + `GIT_CONFIG_GLOBAL=/dev/null`) and never touch the user's repo — `core/checkpoints.py`.

## Architecture — core invariants

- The session log is **event-sourced and the source of truth** (`core/session_log.py`): provider history is *derived* (`derive_messages()`), never stored twice; the model-visible request is `fold_request_header(system) + derive_messages()`. `request/header` records the full non-history envelope (model/max_tokens/context_window/mode/sandbox/reasoning_effort + system prompt + tool schemas) and is appended only when it changed (`initial`/`change`). `config.sandbox` is effective-shell-state audit metadata, NOT model-visible — the model learns a boundary only from denials. `tool/result` carries non-surface audit fields (`riskLevel`, `categories`, `decision` `auto`/`user`/`always`/`denied`, `escalated`).
- Environment context — memory, skills, mode — is injected as **tagged synthetic `user/message` events** (`source: memory` / `skill` / `mode`; also `human`, `compaction`, `interruption`, `memory-recall`, `completion-audit`), never baked into the system prompt, so request prefixes stay prompt-cache stable. Memory is injected on a session's first turn and again only when its text changes (`injections_for_turn` fingerprint; `invalidate_injections` after a compaction that may have folded it).
- `AgentBuilder` (fluent, `core/builder.py`) is the single wiring point: tools, WriteFence, bash/MCP sandbox, subagent types. A `chat/set_mode` change rebuilds the agent so a mode switch re-arms/disarms the boundaries.
- Subagents are child `SessionLog`s linked to the parent by `subagent/spawn`; replay walks the whole delegation tree depth-first (`session_log_store.py`). Recursion is capped at `MAX_SUBAGENT_DEPTH = 4` (root = 0); at the cap the `task` tool is withheld.
- Torn session tails are dropped on load; an interrupted turn is closed with a synthetic `tool/result` + `turn/end {interrupted}`; undo rewinds to a turn boundary via one `truncate`.
- **Completion audit** (`core/completion_audit.py`) — anti-fake-completion: every `end_turn` reply is reconciled against the turn's executed tool calls (denied/malformed/errored calls don't count) and an unsupported claim is bounced back ONCE as a synthetic `source:"completion-audit"` message (advisory, never hard-blocks). A file-change claim needs write-tool evidence and a test/command claim needs a bash call; when only bash ran, the claimed files are verified against the filesystem by `mtime >= turn start` (an unknown path, a deletion or a negated claim ⇒ skip, never bounce). `turn/end.reason.completion_audit = {reminders, unbacked}`. **`unbacked` is what the delegation boundary reads**: a child whose own audit still refuted the reply it committed gets a claimed/bare `success` downgraded to `partial` by `_normalize_status` in `tools/task.py` — the engine's record of what the child did outranks what the child wrote about it. Prompt side: `<completion_protocol>` (`system_prompt.j2`) and the `**Status**: success|partial|failed|blocked` contract (`child_system_prompt.j2`).

## Security: sandbox (READ the docs before touching this code)

Two enforcement boundaries sit behind the permissions policy (`core/permissions.py` decides what is *allowed*; the boundaries make denials stick). Authoritative Chinese docs: `docs/plans/sandbox-current-state.md` and `sandbox-threat-model.md` — read them before touching `tools/_fence.py` / `tools/_sandbox.py` / `core/grants.py`.

- **WriteFence (T1, in-process)** — guards the 5 file tools (`write_file`/`search_replace`/`multi_edit`/`multi_write`/`delete_file`, every item of a batch). Canonicalize-then-contain (`resolve(strict=False)` → deny → contain) before any I/O; enabled in every mode except `yolo`.
  - Writable roots live in exactly one place, `WriteFence.roots()`: session cwd + platform temp + exactly `~/.cluxmate/AGENTS.md` (so `update_memory`'s "edit global entries with search_replace" contract works) + user-granted folders. The rest of `~/.cluxmate` (config.json with API keys, session logs, checkpoints) is off-limits.
  - `<cwd>/.cluxmate/` is a **deny subtree** overriding the roots, because it holds CluxMate's own privileged state (permissions.json always-allow, mcp.json which spawns subprocesses on load, skills.json, lsp.json, agents/): a prompt-injected model must not edit its own permission config. Deny-subtree rejections are NOT openable by escalation.
- **Bash + MCP stdio sandbox (T2, OS-level)** — glue over OS primitives, never from scratch. Linux = bubblewrap mount namespaces (root fs read-only, workspace + temp bind-mounted writable, `<cwd>/.cluxmate` re-mounted read-only LAST so it beats those binds, `--die-with-parent`). macOS = Seatbelt `sandbox-exec` (`(allow default)` minus writes, `<cwd>/.cluxmate` re-denied). Windows = Low integrity-level token + `NO_WRITE_UP` over the workspace tree (icacls, marker `<cwd>/.cluxmate/sandbox-il-applied`), with `<cwd>/.cluxmate` deliberately re-labeled medium and `tmp-low` as the child's TMP/TEMP. Low-IL can still READ everything and reach the network, so `enforcement="partial"` on every backend, by design.
  - **Fail-closed**: sandbox enabled + no backend available ⇒ BashTool refuses to run (never a bare subprocess fallback). Escape hatch `CLUXMATE_BASH_SANDBOX=off` (explicit, env-scoped). The backend is chosen ONCE when tools are built (`pick_sandbox` probes; Windows needs `icacls` on PATH) — changing the env var mid-process does nothing.
  - Windows shell nuance: real Git Bash (MSYS2) is preferred when on PATH, but it CANNOT run under the Low-IL sandbox (NtCreateDirectoryObject 0xC0000022), so BashTool falls back to the cmd.exe `shell_cmd` path; WSL's bash.exe is never the default (its Linux-side DrvFS/interop escapes the integrity boundary).
  - **Per-call escalation**: mutating tools accept `sandbox_permissions="danger-full-access"` + a one-sentence `justification` (paired; validated at execution by `validate_escalation_args`). Requesting it raises the call's risk to `dangerous` so the approval prompt fires BEFORE execution; approval widens the mode for that ONE call (file tools skip fence containment, bash runs unsandboxed).
- `core/grants.py` = the always-allow **writable-folder registry** at `~/.cluxmate/sandbox-grants.json` (user-global, one per user — NOT per-project).
- **Network egress** (bash + MCP stdio, not LSP): `~/.cluxmate/egress.json` `{"mode": "shared"|"off"|"proxy"}` (default `shared`), read by `core/egress_config.py` and baked into the backend at build time. `off` = kernel-level deny (bwrap `--unshare-net`, Seatbelt `(deny network*)`; **Windows fails closed** — Low-IL cannot limit network, so the user is pointed at proxy mode). `proxy` = traffic forced through the loopback allowlist proxy `tools/_egress_proxy.py` (allowlist = ssrf.json's `allow`, empty = deny-all), best-effort. yolo / `CLUXMATE_BASH_SANDBOX=off` disable egress too. Gap: a true Windows kernel-level `off` (AppContainer phase 2).
- **Read denylist** — `~/.cluxmate/forbid-read.json` (`core/read_denies.py`, user-global): an explicit `paths` list plus an opt-in `protect_sensitive` toggle (default OFF = zero behavior change) adding `.env` / `.git-credentials` / `.netrc` and `*.pem`/`*.key`/`*.p12`/`*.pfx`. Enforced at process level by `ReadFence` (read_file/grep/list_dir); `~/.ssh`, `~/.aws` and `~/.gnupg` join `effective_paths()` so bwrap/Seatbelt enforce those too (the Windows Low-IL read side is a documented no-op).

## Hooks

Lifecycle hooks (Claude-Code-style, 9 events): `UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `Stop` / `SessionStart` / `SessionEnd` / `SubagentStop` / `PreCompact` / `Notification`. A hook is a user shell command receiving a JSON payload on stdin (env `CLUXMATE_HOOK_EVENT`) and writing JSON to stdout: `{"decision":"block","reason":…}` / `{"continue":false,…}` / exit code 2 blocks; `{"hookSpecificOutput":{"additionalContext":…}}` injects context; anything else continues. Per-event: a `Stop` block re-runs the turn (max 3, streams `text_restart`); `SessionStart` block aborts startup and its feedback prepends to turn 1 only; `SubagentStop` block replaces the child's reply in the parent; `PreCompact` block skips that step; `SessionEnd`/`Notification` discard output (Notification also fires at turn end on desktop and via `hooks/notify`). `SessionEnd` fires on clean shutdown only, and re-initializing the SAME session_id fires neither SessionEnd nor SessionStart. Config `settings.json` (global then project); RPC `hooks/get` + `reload_hooks`; runs stream as `hook_start`/`hook_result`. **Trust model: hooks are the user's own config — NOT sandboxed, not model output; project hooks are trust-gated too, so an untrusted directory loads no project hook (global hooks still run).** Authoritative doc `docs/plans/hooks.md` (D1–D18); read before touching `core/hooks.py` / `core/agent.py` / `tools/task.py` / `core/jsonrpc_server.py`.

## State & config layout

- Per-project state lives in `<cwd>/.cluxmate/` (with the project, never in home): `permissions.json`, `skills.json`, the project halves of MCP / LSP / hooks (`mcp.json`, `lsp.json`, `settings.json`), `agents/`, `memory/facts/`, `sandbox-il-applied`, `tmp-low`, `tmp-spill/`.
- Global `~/.cluxmate/` holds the global half of each config family (MCP merges **per server name, one level**: `merged[name].update(entry)`, so a project `env`/`headers` object REPLACES the global one while omitted keys are inherited — the loader docstrings call it "deep-merges" and are wrong; hooks run global-then-project), the state stores (`sandbox-grants.json`, `forbid-read.json`, `ssrf.json`, `egress.json`, `trust.json` (project-trust registry; model-unwritable), `retrieval-memory.json`, `lsp.json`), `checkpoints/`, `memory/global/facts/`, `agents/`, `AGENTS.md`, and `config.json` schema v2 — `{"version": 2, "models": [{id, api_type, provider, base_url, api_key, model_name, context_1m, max_tokens, reasoning_efforts?}], "active_model_id"}` (legacy `{providers, default_provider}` migrates in place on load; an empty `api_key` falls back to `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`).
- **Memory files** (`core/memory.py`): AGENTS.md is the only memory file (Codex convention); `CLAUDE.md` (`<cwd>/`, `~/.claude/`) is a read-only fallback when AGENTS.md is absent, and writes always target AGENTS.md. Global renders first, then project, as `<global_memory>` / `<project_memory>` in one `source:"memory"` message. `MAX_MEMORY_CHARS` = 64 Ki **characters** per file, and the cut is `text[:MAX]` — the TAIL is dropped, so the newest entries are the first to disappear; `is_over_limit` compares characters of the file actually read (AGENTS.md, else the CLAUDE.md fallback) — keep both on one unit and one source.
- **Memory discipline** (this file is injected into every session and then kept in its context, so size is real cost): an entry records a *decision / constraint / gotcha that code and git cannot tell you* — no dates, commit shas, test counts, full-suite results, or file-by-file walkthroughs. Fold a new fact into the existing topic section instead of appending a new one (one canonical home per topic), keep a topic ≤ ~1.5 k chars, and put dropped detail in `docs/memory-archive.md` (gitignored, like all of `docs/`).

## Feature decisions

### SSRF guard (`tools/_ssrf.py`)

`web_fetch`/`web_search` are guarded in ALL modes INCLUDING `yolo` (deliberate: it defends against remote prompt-injection, not model intent). `validate_url` blocks 17 default nets (RFC1918/loopback/link-local/metadata/NAT64/`::/96`), hostnames are IDNA-encoded then DNS-resolved per IP with fail-closed on resolution failure, and hop-by-hop validation rides httpx `event_hooks` (which MUST be `async def` on httpx ≥ 0.28). Config `~/.cluxmate/ssrf.json` = `{"allow": [...], "block_extra": [...]}` with `host` / `host:port` / `[ipv6]:port` / IP / CIDR entries; **allow wins over every block**, and the file sits inside the non-writable `~/.cluxmate/`, so the model cannot self-allow. `core/ssrf_config.py` is mtime-cached (an edit takes effect next request, no bridge kill). Accepted gaps: DNS rebinding (TOCTOU), proxy-env mismatch, no getaddrinfo timeout, and MCP-tool network behaviour is unconstrained.

### Retrieval memory (`core/retrieval_memory.py`)

Lexical-first (no embeddings; phase 2): one `.md` per fact under `~/.cluxmate/memory/global/facts/` + `<cwd>/.cluxmate/memory/facts/`, written by `remember`/`forget` (parent-only, write risk, plan-excluded) and recalled per turn into a low-authority `user/message {source:"memory-recall"}` AFTER the human message. Default OFF (`~/.cluxmate/retrieval-memory.json`); facts outlive session deletion.
Hard-won FTS5 constraints (`trigram`, measured on SQLite 3.45.3): a trigram `MATCH` needs **≥ 3 characters** (a 2-char CJK query returns nothing), so `_tokenize` emits CJK **3-char windows**; CJK bigrams are kept separately because 2-char words must still recall. Raw CJK under `unicode61` is one giant token (useless) — it only works when BOTH sides are bigram-ized. `bm25()`/`rank` DO work under trigram. One FTS5 table has exactly ONE tokenizer, so a word/BIGRAM index plus a trigram index needs two virtual tables (fuse with RRF).
**Threading rule**: the in-memory sqlite connection is built on the builder thread but used on the per-turn thread, so it is opened with `check_same_thread=False` and every `_reconcile`+`_search` runs under one `threading.Lock`. Any `sqlite3`/loop-bound resource on an object shared across rebuilds/turns must be built per-thread or explicitly made cross-thread-safe.

### Threading model (JSON-RPC server)

`JsonRpcServer._handle_chat_send` runs EVERY turn on its own fresh daemon thread with its own new event loop and executor, while `initialize` / the MCP loader / `build()` may each run on different threads — never assume a shared object is used on the thread that built it (this is why each turn resets the provider client). An unanswered `ask_user_question` parks a default-executor thread inside `evt.wait()` that `asyncio.run()`'s shutdown joins: any test/script that abandons a waiter hangs at interpreter exit (always `cbs.cancel()` in teardown), and piped stdout buffers until then, which looks like a silent freeze.

### Tool-output bounding (`tools/_output.py`)

Every tool result over `MAX_OUTPUT_CHARS` (40 k **chars**) is bounded by `tools/_output.py` in `BaseTool.run_safe`: head/tail split 50/50, shifted to 70/30 **tail-biased** when `error|traceback|panic` appears near the end, middle replaced by `[... N characters omitted ...]`; a preview trims to a line boundary only for a partial line ≤ 200 chars, and the result is guaranteed ≤ the cap. Overflow spills to `<cwd>/.cluxmate/tmp-spill/` (7-day retention, lazily swept) and the notice carries the path plus a `read_file`(offset/limit)/grep hint. Invariants: never raises (any fs error ⇒ inline truncation, never `is_error`), `read_file` is exempt (no read→spill→read loop), and the write is framework scratch done in-process — NOT through the WriteFence.

### Compaction (`core/context.py`)

Cuts are **tool-pairing balanced** (`_pairing_cut`/`_snap_forward`; a cut is legal only where the unanswered-tool-call balance is 0, covering both the OpenAI and Anthropic message shapes). Preference: the size target if legal, else snap **backward** to the cut opening the group the walk landed inside — backward keeps the freshest call/result pair in the preserved tail; forward is a last resort, and a malformed transcript falls back to a shape rule instead of throwing. Why: an always-forward advance could leave an EMPTY tail, turning the whole recent conversation into a summary.
`SessionLog.surface_generation` (count of surface mutations) is the staleness token: `_compact_step` captures it before `compact()` and re-checks it before logging, re-deriving from the CURRENT surface and recomputing at most once; a surface that keeps moving leaves the step uncompacted (`turn/end.reason.compaction.stale_retries`). Without it, a message appended while the summarizer ran would be logged on the surface but missing from the request, breaking "model-visible ⟺ logged".

### LSP (`core/lsp.py`, `tools/lsp_tool.py`)

One read-only `lsp` tool with 10 ops (goToDefinition/goToDeclaration/goToTypeDefinition/goToImplementation/findReferences/hover/documentSymbol/workspaceSymbol/callHierarchy/diagnostics) and 6 default server specs (python/ts/js/go/java/rust/cpp), all PATH-resolved and never bundled. A missing server returns an install prompt, or auto-installs only when effective `auto_install` is true AND the spec ships an `install_cmd` (`~/.cluxmate/lsp.json` + `<cwd>/.cluxmate/lsp.json`, deep-merged like mcp.json); installers are user config, run unsandboxed and serialized, and `LSPManager.auto_install = mode != "plan"` so plan-mode isolation can never run one. There is deliberately no desktop LSP panel — install hints surface in chat.
**Post-write diagnostics** (`LSPManager.auto_diagnostics` via `tools/_diagnostics.py`, wired into the 4 write tools with an optional `lsp=` kwarg and one shared manager): contract is never raises, never installs, ERROR severity only, `""` when quiet; a server starts only when the binary is already on PATH (an edit must never install a toolchain), and the drain wait is 1 s. Warnings/hints are dropped on purpose (a mid-refactor edit leaves unused-import noise). `delete_file` is not wired.
Caveat on this machine: the PATH `pyright-langserver` never answers `initialize` (it logs a banner then goes silent), so the real-pyright path is unverified here; the wiring is verified against a protocol-conformant fake server. A silent server must be bounded (`_HANDSHAKE_TIMEOUT_SECONDS`, Windows pipe polling via `_pipe_readable`/PeekNamedPipe) — an unbounded `readline` once hung every Python file write.

### Task-list panel sync (`todo_write`)

The desktop panel must never disagree with reality: the loop emits exactly ONE todo update per step, from the post-gather loop, taking the last executed `todo_write` in input order (the same winner the log's fold picks) — emission must stay OUT of `_execute_one`, since a step's tool calls run concurrently and a slower sibling could emit its older snapshot last. `retryMessage` resets `todos` at send (it cannot rely on `turn/start`, which only fires when checkpoints exist), and `switchSession`'s async fold is guarded so it cannot overwrite a list the user already changed (`if (s2.isStreaming || s2.todos !== todosBeforeRestore) return`). The prompt requires one final `todo_write` before the final reply.

### Subagents (`core/subagents.py`, `core/subagent_scheduler.py`, `tools/task.py`)

Types are user-defined markdown (`~/.cluxmate/agents/*.md`, `<cwd>/.cluxmate/agents/*.md`; builtin < global < project, later wins). Frontmatter: `name`/`description` (required), `tools` (whitelist; `task` = the recursion switch, and an unknown or parent-only tool drops the file into `errors`), `model`, `max_turns` (default 50, clamped 150), `subagents` (`none`/`inherit`/`[slug…]`); the body becomes `<agent_instructions>`. Builtins in catalog order `general-purpose, explore, reviewer` — adding one changes that order and several tests assert it.
Admission control is per-event-loop (`SubagentScheduler`; JSON-RPC turns each run on a fresh loop, so never a process singleton): `MAX_CONCURRENT=4` / `MAX_WRITERS=2`, no config surface. `task` takes optional `write_paths`; a writable type that omits it claims the WHOLE workspace (writers serialize by default), read-only types never claim, and a dropped path set falls back to the workspace claim. The scheduler is acquired BEFORE `build_child` and released in `finally`.
Result contract: every child report is prefixed `[subagent: <slug> | status=… | end=… | turns=n/max | out=X tok | Ns | wait=X.Xs]`, where the child's own `turn/end` kind is authoritative and a claimed `success` on an abnormal end is downgraded to `partial` (`_reported_status`/`_normalize_status`/`_result_header`). `general-purpose` keeps 150 turns, other types 50. The `reviewer` builtin has `read_file`/`grep`/`list_dir`/`lsp`/`bash` and no `task` (no recursion), and its evidence gate lives in the PARENT prompt (`<review_gate>`): a per-claim verdict must carry evidence (test name, real command output, or file:line), an evidence-free pass counts as a failure, and re-review beats accepting prose. `bash` is why the reviewer is not `readonly` (it must not race the edits it judges) — hence `can_edit`/`EDIT_TOOL_NAMES` exist as a SEPARATE question from "can run a command" in `child_system_prompt.j2`. Scheduling consequence (measured): a reviewer spawned without `write_paths` claims the WHOLE workspace, so it is admissible only when NO other claiming subagent runs — and two reviewers never run together (their whole-workspace claims overlap each other). A review therefore runs alone; only claimless types (`explore`) or disjoint declared writers co-run. The ordering rule that follows lives in the PROMPT, not the scheduler: `<review_gate>` says a review is a step of its own AFTER the batch (never a sibling of it — siblings are admitted in block order, `_pump` only skipping a still-blocked earlier waiter, so a reviewer listed ahead of the implementers is admitted first, takes the whole workspace and judges an untouched tree) and that a reviewer never gets `write_paths`, and `task`'s `write_paths` description repeats it at the argument the spawner actually picks. Rejected alternative: letting a reviewer declare a scope so it can co-run with unrelated writers — its evidence (`git diff`, the test run) reads the WHOLE tree, and a model-declared review scope is only meaningful if the host cross-checks it against read evidence (the Reasonix `review_report.go` rule), which nothing here does.

### Skill name collisions (global vs project root)

Same dir **slug** in both roots: the nearest ENABLED copy serves it (a disabled project copy falls back to the global one). `SkillManager.discover()` returns BOTH copies with `shadowed=True` on the skipped one (enabled only — a disabled copy is merely off); the agent-visible surfaces (the injection, `use_skill`, its error text) show ONE row per slug, sorted for prefix-cache stability, and `use_skill` names the overridden copy in its result instead of marking the injected list. Disable state is `<cwd>/.cluxmate/skills.json` → `disabledSkills` with per-copy ids `<source>:<slug>`; a bare slug is still READ as "every root" (legacy files), and every desktop write first rewrites bindable bare entries into per-copy ids or a per-copy toggle could not be expressed. Desktop: `shared/skill-rules.ts` holds the pure rules imported by BOTH the main process and the renderer store (so the marker is re-derived on each optimistic toggle and cannot go stale), `main/skills.ts` the fs half; both readers tolerate a malformed or non-object `skills.json`.

### MCP OAuth (remote HTTP servers)

Layering: `core/mcp_auth_store.py` (the `~/.cluxmate/mcp-auth.json` credential file + URL-identity rules) ← `core/mcp_oauth.py` (RFC 9728 → 8414/OIDC → 7591 DCR → PKCE S256 engine, synchronous httpx, owns the loopback callback, **never writes to disk**) ← `core/mcp.py` (config parsing, per-request bearer injection, the 401 ladder). OAuth is for `url` (http) transport only; `oauth` on a stdio server is a hard config error.
Credential precedence: explicit `oauth:{…}` (a truthy non-object like `true` = enable with defaults) > `oauth:false` off > a non-empty static `Authorization` header (case-insensitive, non-string values neither suppress nor raise) > **latent** OAuth (http, no static header — a stored token is attached if present, and a 401 becomes `needs_auth`). `client_secret_env` holds an env var NAME.
`needs_auth` is a status distinct from `failed`: it means "the user has an action" (desktop login button / `cluxmate mcp auth <name>`), `failed` means read the error. Expired + refresh token ⇒ silent refresh; a deterministic `refresh_rejected` deletes the credentials, a transient failure keeps them and reports `failed`. A 401 may trigger exactly ONE forced refresh + retry per call. The engine's `OAuthError.kind` `denied`/`cancelled`/`timeout` are preserved verbatim in the `mcp/auth/completed` notification; everything else is `failed`.
Storage: 0600, atomic temp+replace, **content-compared** freshness (not mtime/size — Windows' ~15.6 ms file clock plus same-length token rewrites make a signature miss the write) so a long-lived reader sees the RPC thread's write; cross-process writes are last-writer-wins (no flock, same contract as `config.json`). `~/.cluxmate/mcp-auth.json` is ALWAYS in `ReadDenyStore.effective_paths()` (independent of `protect_sensitive`), but `snapshot()` still hides it from Settings.
`mcp/auth/start` must never block: `_dispatch` runs on the single stdin thread, so the flow runs on a daemon thread and reports through `mcp/auth/completed`; success hot-swaps ONE MCP client (`MCPManager.reload_client` → `AgentBuilder.reload_mcp_server`, guarded by `_init_gen` AND the manager/builder `_closed` latches) and rebuilds the agent only when the tool set changed. No `mcp/auth/*` TOOL exists — the model must have no way to trigger authorization.
Both MCP HTTP calls post the ABSOLUTE `self.config.url`: httpx normalizes `base_url` to a trailing slash, so the old relative `post("")` 404'd against any endpoint whose path is not `/` (and `notifications/initialized` never reached the server).
Tests: `tests/core/fake_mcp_http_server.py` is one loopback server playing BOTH resource server and AS (same-origin rules require that) with a knob per rejection; never a real browser or network.
Load semantics that the UI/docs must not get wrong: `disabled: true` does NOT skip starting the server — `MCPManager.load()` builds and handshakes a client for every config (only `_rebuild_tools` filters), so "禁用 ≠ 不运行"; and the MCP stdio sandbox is **best-effort** (`_sandbox is None` ⇒ bare `Popen`), unlike bash which is fail-closed — the same `pick_sandbox` backend and egress kwargs are shared (`builder.py` `_shell_sandbox`/`_mcp_sandbox`), so the only difference is the no-backend fallback.

### Desktop-only patterns

Attention flash (taskbar): the RENDERER derives "any session has a pending card" from `sessionStates` (never a maintained flag) and sends `window:set-attention`; macOS must use `app.dock.bounce('critical')` + `cancelBounce` (`flashFrame` there maps to a single informational bounce), Windows/Linux use `win.flashFrame` with a Windows re-assert timer. Desktop-only prefs (theme/font/lang/attention) live in renderer localStorage with no `~/.cluxmate/*.json`, no bridge kill and no Python/RPC — the pattern to copy. New `SettingsView` sections need a `SECTIONS` entry plus matching `en`/`zh` keys (`zh: Record<keyof typeof en, string>` typechecks parity). Config changes that the running agent cannot hot-swap (grants, forbid-read template, MCP) must kill and respawn the bridge, unlike mtime-cached configs (ssrf).
**Layout gotcha: a full-page pane swapped into App's column must carry `min-h-0` on its `flex-1 flex flex-col` root** (Skills/Settings/SubagentFocusView do; the MCP help page did not, and rendered truncated): a flex item's automatic minimum size is its CONTENT height, so without it the pane grows past the viewport, gets clipped by the row wrapper's `overflow-hidden`, and its inner `overflow-y-auto` body never receives a bounded height to scroll within — the body does NOT need `min-h-0` itself (an `overflow`≠`visible` box has automatic min size 0).

### Token accounting (`AgentLoop.turn_usage` / `on_usage`)

- A turn's LLM totals (input/output tokens, cache_read/cache_write, ttft_ms, gen_ms) live in ONE place: `AgentLoop.turn_usage` (built by `_empty_turn_usage()`), re-initialized at `_run_loop` entry. EVERY terminal path reports them — the token fields via `_turn_cache_usage()`, the timing fields read straight off `turn_usage`. `_fail_turn` (provider/network error) previously returned neither, and the max-turns stop previously returned no `cache_usage`.
- `AgentCallbacks.on_usage` publishes the *running* total after each LLM call; JSON-RPC forwards it as `chat/stream {type:"usage", agent_id:"root", …}`. `ScopedCallbacks` deliberately does NOT override `on_usage`, so subagent totals ride `agent_end` only (never double counted).
- Desktop: the `usage` event writes the reply's `cacheUsage`/`timing` in BOTH the `sendMessage` and the `retryMessage` stream handlers, and NO path may write those fields back to `undefined` — a cancelled or timed-out turn's ChatResult carries NO `usage`/`timing` (the RPC answers `{stop_reason, text, history}` only), so a cleared field drops that turn from the footer (measured: one real session's footer read 6.37M root input while 72.08M was actually sent, 91% missing — turns `max-turns`/`interrupted`/`error`/`aborted`).
- `on_usage` also carries `turn` / `step` / `time` (epoch ms, the log's own clock) so the renderer can drop a superseded turn's late event (`isStaleUsage` in the store, used by BOTH stream handlers) instead of applying it to the reply now streaming; a null `turn` (no session log) or missing `time`/`step` (older bridge) must stay APPLICABLE — a false negative silently under-counts, which is worse than the blip it prevents.
- A cancelled child: `tools/task.py` now catches `asyncio.CancelledError` separately (a BaseException the old `except Exception` never saw) → `_report_cancelled_child` reports status `error` + the tokens already burned (from the child's own loop total) and then re-raises; best-effort (`except BaseException: pass`) so it can never replace the cancellation. This does NOT make SubagentStop hooks universally off on cancellation — a turn-level cancel that surfaces as the JSON-RPC `_CancelledError` (a plain Exception raised by `ScopedCallbacks`) still takes the `except Exception` path, which does run them.
